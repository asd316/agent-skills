# 答案格式：骨架 · 脊柱 · 血肉 · 由浅入深

最终交付物是一份单文件 HTML 报告（以 `assets/report-template.html` 为底稿）。本文件规定内容结构与铺排逻辑。

## 叙事逻辑：由浅入深的四层

报告正文按四个层次推进，每层解决读者一个阶段的问题：

1. **L0 速览**：一句话回答用户的问题 + 3–5 条核心结论卡片。让 30 秒的读者也能带走答案。
2. **L1 直觉图景**：用大白话和比喻说明"这个问题到底是怎么回事"，不引用任何人名。先建立画面。
3. **L2 智者登场（骨架）**：逐一介绍人物/学派——他是谁、他怎么看这个问题、他的代表性论断。卡片式呈现，标注主流/边缘与争议。人物之间的关系用一张谱系图（HTML/CSS 绘制）展示：谁继承谁、谁反对谁。
4. **L3 方法脊柱（脊柱，全文重心）**：把每位智者的**思考方法**抽出来，按由浅入深排序，作为一条纵向主线逐节展开。每节回答：这个方法是什么 → 为什么这样看问题 → 用它在本问题上能推出什么 → 它的盲区。血肉（案例、数据、历史细节）全部挂在这一层的方法节点上。
5. **L4 批判与综合**：各派在哪里真正冲突（不是立场的对立，而是前提的对立）、当前证据更支持谁、各自的盲区，最后给一个诚实标注了不确定性的综合判断。

## "骨架—脊柱—血肉"的操作定义

- **骨架**：人物/学派清单及其关系。决定报告的章节划分。
- **脊柱**：从人物身上提炼的思考方法序列。决定报告的叙事顺序——读者读完记住的不是"某人说了什么"，而是"这个问题有 N 种真正的看法，各自怎么看"。
- **血肉**：AI 重新组织的论证、案例、数据、比喻。血肉必须服务于方法节点；与任何方法都无关的素材，删掉。

## 图文并茂的规范

所有图示用内联 HTML/CSS/SVG 绘制（模板已含样式），禁止外链图片：

- **谱系图**：人物关系图（节点 + 连线 + 关系标签），放在 L2 开头。
- **方法脊柱图**：纵向时间线式的主线图，每个方法一个节点，放在 L3 开头，让读者一眼看到全文的"脊柱"。
- **人物卡片**：首字母头像（不用真人照片）、定位、光谱徽章（主流=深色 / 边缘=琥珀 / 跨界=绿）、核心方法一句话。
- **结论卡片**（L0）与**冲突对照表**（L4，两列摆对立观点与各自前提）。
- 关键术语用 `<mark>` 或高亮样式；每个方法节点配一个具体案例块。

## 长度与深浅控制

- 单份报告正文以读完 8–15 分钟为宜；宁可砍掉第二位重复的人物，也不稀释方法脊柱。
- 每个方法节点至少一个"如果用它来看本问题，会得到……"的应用段，避免方法悬空。
- L4 的综合判断必须给出不确定性说明："在 X 前提下采信 A 派，若 Y 成立则 B 派更对"。

## 输出要求

- 单文件 HTML，CSS 全部内联，中文排版（衬线标题 + 无衬线正文或反之，模板已定）。
- 保存到当前工作区：`sage-report-<领域slug>-<YYYYMMDD>.html`。
- 文末附"知识库更新记录"：本次新建/增量了哪些人物档案。
